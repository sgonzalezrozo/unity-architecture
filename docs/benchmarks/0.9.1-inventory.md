# Baseline 0.9.1: multi-source bento inventory

The reference for 0.9.2: the same request, run headless against the same project state, measured with the timing hook.

## Setup

- Project: MyTools, rules 0.9.1, profile `fast-ioc`, `ui-scroller`, `screen-system`, `ui-foundations`. Editor closed, so the Stop hook verified in batch mode.
- Prompt (feature folder `InventoryN`): *"Creame un sistema de inventario basico en esta carpeta Assets/Client/InventoryN con tres fuentes: armamentos, escudos y pociones y arma una lista multi source bento. Solo código. tests: Assets/Client/InventoryN."* plus a line approving the plan in advance, since a headless run can't answer questions. The time a person spends answering the scope question isn't in these numbers.
- `claude -p --permission-mode auto`, default model. Each run started from the same snapshot of `Assets/`, `ProjectSettings/` and `Packages/`, with no other inventory feature in the project.
- Run 3 stopped after 1 min 23 s on the account's usage limit, still reading rules. It is left out.

## Numbers

| | Run 1 | Run 2 |
|---|---|---|
| Wall time | 5 min 45 s | 5 min 18 s |
| Time to the first file written | 3 min 26 s | 3 min 24 s |
| Tool calls before the first write | 17 | 23 |
| Tool calls in total | 23 (22 Bash) | 28 (27 Bash) |
| Stop hook verification | 21 s | 20 s |
| Turns, cost | 25, 1.39 USD | 29, 1.36 USD |

About 60% of each run goes by before anything is written. Almost every call is Bash: the agent reads the rules with `cd` and relative paths, which the 0.9.1 logger can't attribute to a rule document, so most of that time shows as "Shell commands".

## What came out

The same in both runs:

- `IMPLEMENTATION.md` at the feature root, with the six sections of `HAND-07` in order (110 lines each).
- Model on the screen root (`InventoryModel : MonoBehaviour`) with the configuration asset injected (`MODEL-12`).
- `Services/{Feature}Config.cs` and `Services/{Feature}Installer.cs` binding it, scene `Frontend`, priority 200 (`DI-11`).
- `SectionedScroller<InventoryItemData, InventorySectionData>`, item and header slots, `InventoryBentoLayout.json` (`LIST-10`).
- A screen folder named `Inventory/` inside the feature, and `Logs/verify/test-scope` written.

Different:

| | Run 1 | Run 2 |
|---|---|---|
| Root View | `InventoryListView` | `InventoryView` |
| Model | plain | also `ISectionedSourceProvider` |
| Installer binding | `FromInstance(CONFIG_PATH)`, a path constant | `FromInstance("Inventory2Config")`, a name |
| Files outside the feature | none | `Client.asmdef`: added `Unity.Localization` |

## Gaps found

1. **The config asset isn't created in a code-only scope.** Both runs left `{Feature}Config.asset` to the person in `IMPLEMENTATION.md`, but the installer already binds it. Until someone creates it, Fast IoC generation fails for that scene. A configuration asset is data, not a prefab: it should be part of the code.
2. **Names the rules don't fix:** the root View of a list screen, and how `FromInstance` names the asset.
3. **Unrequested assembly change:** run 2 added `Unity.Localization` to `Client.asmdef` without asking.
4. **Reading is still the largest stage.** 17 to 23 calls and about 3.5 min before the first write.
5. **The logger misses most rule reads** (paths relative to a `cd`).

## Targets for 0.9.2

- Before the first write: at most 5 calls and under 1.5 min.
- Two runs plan and write the same files with the same names.
- Every gap above is either fixed by a rule or caught by the Stop hook.
